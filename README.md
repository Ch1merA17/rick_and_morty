# Rick and Morty: каталог персонажей

Flutter-приложение для просмотра и поиска персонажей вселенной Rick and Morty на основе [Rick and Morty API](https://rickandmortyapi.com/documentation).

## Возможности

- Сетка персонажей с изображением, именем и статусом; число колонок подстраивается под ширину экрана.
- Постраничная загрузка при прокрутке, pull-to-refresh.
- Поиск по имени с debounce; ответы на устаревшие запросы отбрасываются.
- Состояния загрузки (скелетон), ошибки с повтором, пустого результата, ошибки догрузки страницы.
- Экран персонажа: имя, изображение, статус, вид, пол, происхождение, текущая локация, число эпизодов.
- Возврат к списку с сохранением прокрутки, загруженных страниц и поискового запроса.
- Hero-переход изображения, поочерёдное появление блоков на экране деталей, отклик карточек на нажатие, защита от двойного тапа.
- Светлая и тёмная темы с сохранением выбора.

## Запуск

```bash
flutter pub get
flutter run
```

## Стек

- Flutter 3.44, Dart 3.12
- `flutter_bloc` (Cubit) — управление состоянием
- `http` — REST-клиент
- `cached_network_image` — загрузка и кэширование изображений
- `shared_preferences` — сохранение выбранной темы

## Архитектура

```
lib/
├── app/            # AppAssembly (DI), AppRouter, корневой RouteGenerator
├── common/         # тема, тексты ошибок, утилиты
├── components/     # переиспользуемые виджеты
├── data/           # ApiClient, хранилище настроек
├── domain/         # общие ошибки, сущности и интерфейсы
└── characters/     # фича
    ├── domain/     # Character, CharactersRepository, CharactersRouter
    ├── data/       # маппер JSON, реализация репозитория
    └── ui/         # экраны (cubit + state + page), роутинг фичи
```

- **Слои.** `domain` не зависит от `data` и `ui`. UI работает с интерфейсами репозиториев и роутера, конкретные реализации подставляет `AppAssembly`.
- **DI** без сторонних библиотек: `AppAssembly` хранит глобальные зависимости в `late final` полях, фабрики экранов вынесены в extension фичи `CharactersAssembly`.
- **Навигация** через `Navigator` и именованные маршруты. Cubit'ы зависят от интерфейса `CharactersRouter` и не знают про `BuildContext`.
- **Ошибки.** `ApiClient` переводит сетевые сбои и коды ответов в sealed-иерархию `AppException`, UI выбирает текст и иконку через исчерпывающий `switch`.
- **Пустой поиск.** API отвечает на него 404, репозиторий превращает это в пустую страницу, а не в ошибку.
